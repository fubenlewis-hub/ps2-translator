# 《通用 PS2 游戏一键汉化工具》技术调研报告

> 调研日期：2026-08-16
> 调研对象：工作区内的两张真实盘（心跳回忆2 音乐视频剪辑版 SLPM-65118、心跳回忆3 SLPM-65080），均为只读分析，未做任何修改。
> 结论先行：**本项目可行**。心跳回忆3 的文本位置与容器结构已全部摸清（含第三方的 QuickBMS 脚本佐证）；心跳回忆2（工作区这张盘）是视频剪辑盘、文本量极少，工具将按通用插件支持，并优先把心跳回忆3 跑通全流程。

## 二、心跳回忆系列（PS2）格式实测发现

### 2.1 心跳回忆2 · 音乐视频剪辑版（SLPM-65118，0.74GB CD）

```
/SYSTEM.CNF   BOOT2 = cdrom0:\SLPM_651.18;1
/SLPM_651.18  游戏 ELF（993KB）
/MODULES/*.IRX  IOP 驱动
/DATA.DAT     704MB 单一容器 —— 全盘内容都在里面
```

**DATA.DAT 容器格式（已完全破解）**：
- 文件头 0x3000 字节 = 目录表，共 **364 条**，每条 32 字节：
  - `u32 绝对偏移` + `u32 大小` + `char[24] 文件名`（内含 `SE\`、`1\`、`2\` 等子目录路径）
- 内容构成：`SE\CISE*.BIN`（视频剪辑）、`BGM\CIBG*.BIN`（音乐）、`VOICE\CIVO*.BIN`（语音）、
  `1\100~125.BIN`、`2\2000~2014.BIN`、`3\300~3xx.BIN`、`4\400.BIN`（**交互场景文件**）、
  `0\TITLE00.BIN`、`MAINMENU.BIN`、`*_BG.BIN`（菜单界面）

**文本结论**：场景文件以魔数 `2A C9 43 F7`（Konami 图形/界面容器）开头，经 Shift-JIS 全文扫描**几乎不含可读文本**——本盘是"音乐视频剪辑"盘，字幕与台词烧录在 CISE 视频流中。**真正的心跳回忆2 游戏本体（SLPM-65123 等）不在工作区**。本工具对该盘提供：容器解包 + 通用字符串扫描 + 手动导入导出兜底；对游戏本体则提供可扩展插件接口，待用户放入本体 ISO 后适配。

### 2.2 心跳回忆3（SLPM-65080，4.68GB DVD）——重点支持对象

```
/SYSTEM.CNF     BOOT2 = cdrom0:\SLPM_650.80;1
/SLPM_650.80    ELF 4.46MB —— 含 DATA*.BIN 的目录表（关键！）
/IOP/*.IRX      IOP 驱动
/DATA1.BIN      614MB  ATP 容器（图像/模型/事件）
/DATA2.BIN      152MB  疑似 GS 纹理/字库容器（头部有 32 级阶梯调色板）
/DATA3.BIN       27MB  ATP 容器（含大量剧本文本！）
/DATA4.BIN       33MB  GS 纹理/字库容器（0x50 起 32 级调色板 + 字形位图区）
/DATA5.BIN       10MB  MIPS 程序 + 未压缩对话文本（最大文本源！）
/EVSDATA.BIN    781MB  视频流
/BSD_DATA/*.BSD 9 个 25~66MB —— 实测为 MPEG-2 视频流（过场动画），非文本
/SOUND/*         Konami 标准音频容器（HEAD/CLIP/STR + DATA.CAT）
```

**关键机制（ELF 内嵌目录表，BloodRaynare QuickBMS 脚本佐证）**：
- DATA1~5.BIN **没有自己的 TOC**，目录表内嵌在 ELF 中三处：
  - `0x199008~0x19A748`、`0x19B360~0x1B2468`、`0x41D4C0~0x422870`
- 每条 8 字节：`u32(高 8 位=容器编号 ARC_NUM，低 24 位=扇区号) + u16 压缩尺寸 + u16 解压尺寸`
  - 容器编号：DATA1=2、DATA2=3、DATA3=4、DATA4=5、DATA5=6
  - 实际偏移 = 扇区号 × 0x800，尺寸 × 0x800
- DATA1/3 内条目以 `41 54 50 00`（"ATP\0"）为魔数，**ATP 是 Konami 自定义压缩**（TM3_Tools 作者在 ResHax 确认对话在压缩条目里，解压算法为 WIP）

**文本位置与格式（本工具实测）**：

| 位置 | 文本量 | 格式 |
|---|---|---|
| **DATA5.BIN**（未压缩） | 3764 条长文本 / 27.5 万字符（另含大量短条目，总量估计 4~6 万条） | Shift-JIS；`0x0D`(CR) 换行；句尾常用 `81 63 81 42`（～。）；行间夹控制码（如 `10 0E 02 22 C8 03` 疑似颜色/属性+长度）；文本块零散分布于文件，前后紧邻 MIPS 代码与数据 |
| **DATA3.BIN**（ATP 压缩内） | 295 条长文本 / 7513 字符（还有更多在未解压条目中） | 剧情叙述/角色对话，含「角色名」台词形式（如 `二宮「…」`） |
| **ELF** | 448 条 / 10431 字符 | 系统文本，含 `%s` 占位符（毕业结局等动态拼接） |

**字库位置（初步）**：DATA2.BIN / DATA4.BIN 为 PS2 GS 纹理容器；DATA4.BIN 0x50 起为 32 级阶梯调色板（4 字节/项：`RGB+0x80` 透明），其后为字形位图区；贴图格式已确认可用 TiledGGD 查看（ResHax 主题 702）。**精确字形布局/映射表需在插件内继续逆向**（可用 TiledGGD 可视化辅助）。

### 2.3 对"通用性"的支撑结论
- TM3 的三层结构（ISO → ELF 内嵌 TOC 的 BIN 容器 → ATP 压缩条目/裸文本）是 Konami PS2 游戏的典型套路，TM2 盘的 `2A C9 43 F7` 图形容器、`DATA.DAT` 目录表亦是同类思路——**插件化三层架构（ISO/容器/文本格式）可覆盖大多数 Konami 游戏，并为其他厂商游戏留出扩展位**。
- 文本编码以 Shift-JIS 为主（cp932 可直接处理）；控制码需按游戏维护白名单。

## 三、推荐开发语言与架构

### 3.1 技术选型
| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | **Python 3.13** | 二进制处理生态最顺（pycdlib/pillow/cp932 内置）、开发快、便于逆向迭代 |
| GUI | **PySide6（Qt6）** | 需求推荐；跨平台、QTableView 适合术语表/文本校对 |
| ISO | **pycdlib** | 提取/重打包 ISO9660；PS2 还涉及 LBA 保序（参照 xpert），打包时按原始布局重建 |
| 翻译 | **OpenAI 兼容 + Anthropic 兼容 HTTP 客户端**（requests） | 云 API 与本地 Ollama/LM Studio 统一为 OpenAI 兼容接口 |
| 字库 | **Pillow** 渲染 → 点阵化 | 12x12/16x16 位图；GB2312/常用 3500 字 |
| 导出 | JSON（主）/ CSV / XLIFF | 人工校对友好 |

### 3.2 插件化架构（三层）
```
┌─ 插件层 1：ISO/容器识别器  ── TM3_ELF_TOC · TM2_DATA_DAT · 通用扫描
├─ 插件层 2：文本格式解析器  ── TM3_DATA5 脚本 · ATP 解压钩子 · 通用 SJIS 运行提取
├─ 插件层 3：字库注入器      ── TM3_GS_Texture 字库 · 通用点阵替换
└─ 核心引擎：工程管理 / 提取 / 术语表 / 翻译 / 回写 / 打包 / 备份回滚
```
插件接口（最小集）：`detect(游戏特征) → bool`、`extract(files) → TextFile[]`、`writeback(TextFile[], translated) → 差异补丁`、`font_support() → 字库方案`。内置插件按"detect 命中"优先，否则回退通用规则；用户可手动指定。

### 3.3 目录规划（初步）
```
ps2-translator/
├── main.py / cli.py           # GUI / 无头 CLI 双入口
├── ps2hantool/
│   ├── iso.py                 # 提取/重打包（LBA 保序）
│   ├── project.py             # 工程状态、备份、断点续传、日志
│   ├── text/                  # 文本模型、导出导入、通用提取器
│   ├── plugins/               # tm3 / tm2_dat / generic_sjis
│   ├── translate/             # 引擎、术语表、网络搜索、术语统一
│   ├── font/                  # 点阵生成、注入框架
│   └── ui/                    # PySide6 页面
├── docs/                      # 调研报告 / 使用说明 / 故障排查
└── research/                  # 调研脚本（只读分析）
```

## 四、工作量预估与风险点

### 4.1 工作量（按里程碑）
| 里程碑 | 内容 | 相对工作量 |
|---|---|---|
| M1 原型 | ISO 提取/打包 + TM3 文本提取 + OpenAI 翻译 + 基础 GUI 流程 | 中（3~5 天） |
| M2 核心 | TM3 回写（控制码/CR 换行/长度适配）+ 术语表+网络搜索 + 本地 AI | 中高（5~8 天） |
| M3 字库 | TM3 字库容器逆向 + 中文点阵生成注入 + 模拟器验证 | **高（7~14 天）**，最大不确定项 |
| M4 通用化 | 插件文档 + TM2 本体适配 + 断点/回滚完善 | 中（3~5 天） |

### 4.2 主要风险点与对策
1. **ATP 压缩解压（高）**：TM3_Tools 作者至今未完成。对策：文本主线走 **DATA5.BIN（未压缩，27.5 万字已可提取）**；ATP 解压作为增强项，接入 Ghidra/PCSX2 逆向或在 ResHax 协作；
2. **字库逆向（高）**：字形布局/映射表未完全破解。对策：三级降级——①完整字库替换（成功则最佳）②字模替换（原字库内重映射）③"同音字/占位"降级并在报告中说明；先用 TiledGGD 可视化辅助；
3. **回写长度与指针（中）**：中文短于日文一般没问题；超长用填充/指针修正，借鉴 Chobits 项目经验；MIPS 4 字节对齐；
4. **TM2 盘文本少（中）**：视频剪辑盘本身可译文本极少，需在文档中说明；游戏本体 ISO 到位后走通用插件；
5. **打包 LBA（低）**：重打包必须保序 + 保留系统区，参照 xpert/pycdlib 已验证能力。
